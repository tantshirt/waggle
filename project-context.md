# Project Context for AI Agents

_Critical rules and patterns AI agents must follow when implementing code in this project.
Focused on unobvious details an agent would otherwise miss._

**Authority:** these rules are derived from the architecture spine
(`docs/planning-artifacts/architecture/spine-waggle-2026-07-28/ARCHITECTURE-SPINE.md`). Where
this file and the spine disagree, the spine wins — and the disagreement is a bug in this file.

---

## What this project is

waggle is a **distribution**, not an application and not a fork. It self-hosts Buzz — an
unmodified upstream Nostr relay — and adds a compilation layer that turns a BMAD Method
installation into things Buzz already consumes: persona packs, workflow YAML, channels,
canvases.

Two systems bound it, and **waggle owns neither**:

- **Buzz** (the *substrate*) — external, immutable, pinned at `v0.4.26`.
- **The BMAD Method installation** (`_bmad/`, `.claude/skills/`) — read-only input.

Most mistakes in this codebase will come from forgetting that.

## Critical Implementation Rules

### 1. Never modify the substrate (AD-2)

The Buzz checkout lives at `vendor/buzz/` and is gitignored. **No code path, script, test, or
convenience edit may write to it.** CI asserts the checkout is byte-unchanged after the full
suite. If something appears to require a Buzz change, it does not get made locally — it gets
logged in `docs/upstream-issues.md` as an upstream candidate and left unimplemented.

### 2. The method installation is read-only, with exactly two exceptions (AD-3)

Read anywhere under `_bmad/` and `.claude/skills/`. **Write only** to `_bmad/custom/` and
waggle's own output directory. `_bmad/config.toml` is regenerated by every
`bmad-method install` — anything written there is destroyed on the next install.

### 3. `waggle-core` performs no I/O (AD-1)

No dependency that opens a file, socket, process, or **clock**. Pure functions over owned
types. Everything depends on it; it depends on nothing of ours. Adding `tokio`, `reqwest`, or
`std::time::SystemTime` to `waggle-core` is a defect, not a shortcut.

### 4. Compile output must be byte-reproducible (AD-4)

No timestamps, absolute paths, hostnames, env vars, or random values in generated artifacts.
Every generated collection has a declared deterministic order. Generated config is committed
and diffed, so nondeterminism shows up as noise in every review.

### 5. The resolver differential test is not optional (AD-5)

waggle ports BMAD's base → team → user merge natively. A test runs BMAD's own
`_bmad/scripts/resolve_customization.py` over every installed agent and asserts equality.
**This test may not be skipped, excluded, or marked allowed-to-fail in CI.** Rust was chosen
over Python knowing this is the cost; do not quietly reduce it.

Merge rules to reproduce exactly: scalars override · tables deep-merge · arrays of tables
keyed by `code`/`id` replace matching entries and append new ones · all other arrays append.

### 6. Nothing is dropped silently (AD-6)

Every descriptor field and menu item is mapped, carried as instruction material, or
**explicitly reported as dropped with a reason**. An unrecognized field is reported as
unknown — never ignored. A module producing zero output is a warning, not a success.

### 7. A menu item is a sum type (AD-7)

Two variants: a **dispatchable reference** compiles to exactly one workflow; a **prompt**
compiles to persona instruction material and **no workflow**. Hitting a prompt variant is
normal control flow, not an error. TEA's `GATE` item is a prompt — the pilot module already
breaks any uniform assumption.

### 8. Secret key material never crosses the identity port (AD-14)

An `nsec` stays inside `waggle-hive`'s identity adapter, in a type with **no `Debug` and no
`Display`**. Never returned across the port, never logged, never printed, never in generated
output or a compile report. This is the one failure with no remediation. A test enforces it.

### 9. Event kinds: standard first (AD-8, AD-9)

- Use a standard kind wherever one exists: `9` group message, `7` reaction, `1617` NIP-34
  patch, `1630`–`1633` NIP-34 status.
- **Forbidden:** `40002` / `40003` — Buzz-only; they work on the wire but no standard client
  reads them, which breaks the portability the product claims.
- **Never use:** reserved substrate ranges `43001`–`43006`, `46001`–`46012`, `48001`.
- **Never use for auditable state:** ephemeral `20000`–`29999` — the relay does not store it.
- Claiming a custom kind requires a written rationale in the committed kind registry.

### 10. The event log is the authority on gate state (AD-10, AD-11)

Buzz currently marks approval-step workflow runs **failed** rather than suspended (upstream
`WF-08`, tracked as UP-01). Therefore:

- Gate state is derived by reading the log — pair verdict events with the approval reactions
  referencing them. **Never** read gate outcome from substrate run status.
- Exactly one crate, `waggle-gate`, may call the substrate's approval mechanism. A structural
  test enforces this.
- A test asserts Buzz's *current broken* behavior. When upstream fixes it, that test fails on
  purpose — that is the tripwire, not a flake. Re-pin deliberately; do not delete the test.

### 11. Verdicts are closed and rationale-gated (AD-12, AD-13)

`PASS` · `CONCERNS` · `FAIL` · `WAIVED` — nothing else. `CONCERNS` and `WAIVED` require a
non-empty rationale, **rejected at publish time, not read time**. Authorization comes from the
relay-signed admin list (kind `39001`); `WAIVED` requires the owner role. waggle publishes no
approver roster of its own.

### 12. Templates are data; no module-specific branches (AD-16)

A conditional on a module identifier anywhere in `waggle-core` or `waggle-emit` is a defect.
Adding module support means adding template data and nothing else. This is the structural form
of counter-metric SM-C1 — special-casing the pilot to make it compile defeats the entire
reason for having a pilot.

### 13. Discover, don't assume, how bodies materialize (AD-19)

`skill-manifest.csv` `path` values point at files that **do not exist on disk**. Treat that
field as a logical identifier and resolve the real body through the tool directory recorded in
the installation manifest. Never hard-code `.claude/skills/`.

### 14. Fail loud, fail specific (NFR-4)

Every failure names the specific artifact, module, service, or version involved. Silent
partial success is a defect. One error enum per crate, non-exhaustive; no stringly-typed
errors cross a port.

### 15. Machine-first commands (AD-20)

Every command emits structured output on stdout with diagnostics on stderr, completes without
interactive input, and uses the fixed exit-code taxonomy: success · user error ·
upstream-contract error · system failure.

## Naming conventions

- Crates: `waggle-<layer>`; domain crate is `waggle-core` (mirrors `buzz-core`).
- Domain types use PRD §3 Glossary terms **verbatim**: `Hive`, `Module`, `AgentDescriptor`,
  `MenuItem`, `PersonaPack`, `CompiledWorkflow`, `AgentIdentity`, `ArtifactEvent`, `Handoff`,
  `Gate`, `Verdict`, `GateRecord`. A synonym in code is a defect.
- Ports: `<Noun>Port` trait, `<Adjective><Noun>Adapter` implementation. The gate port is
  `GateBackend` (name fixed by AD-11).
- Generated files: `<module>/<agent-id>.pack.json`,
  `<module>/<agent-id>.<menu-code>.workflow.yaml`.
- Event tags: lowercase kebab-case, `waggle-` prefixed where waggle-specific.
- Priorities: `P0`–`P3` exactly; no other priority vocabulary anywhere.

## Legal and naming constraint

"BMad", "BMad Method", "BMAD-METHOD" and related marks belong to **BMad Code, LLC**. They may
**never** appear in waggle's product name, crate names, binary names, domains, or branding.
Descriptive compatibility statements only ("compatible with the BMAD Method"). waggle is
independent and unaffiliated; the no-endorsement statement lives in `NOTICE`.

Our license is **Apache-2.0**; the method is MIT. MIT material is one-way compatible inbound
and retains its notice.

## Working agreements

- **Conventional commits.** Commit messages explain *why*, not just what.
- **Push after each accepted story** (Phase 3 discipline).
- **Ask before:** adding a dependency outside the three ecosystems, and any push beyond the
  agreed flow.
- **Traceability:** every design doc states which of the three source repos each concept comes
  from — `[BUZZ]`, `[NOSTR]`, `[BMAD]`, `[WAGGLE]`.
- **Open questions go in writing.** An unknown recorded as an open question is fine; an unknown
  papered over with a guess is not.
